# 城市供水厂制水运行与供水调度管理平台

面向水厂台账、取水泵组、混凝加药、沉淀池运行、滤池反冲洗、消毒加氯、清水池调蓄、出厂水质检测、供水调度指令、管网压力监测、二次供水泵房、水表抄见、爆管抢修、原水监测、阀门井巡检、药剂领用、设备维护与值班交接的一体化城市供水制水调度工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `waterworks-ops:entries` 这一项，或调用 `resetModule(模块)`。

## 滤池反冲洗单据的管控规则

滤池模块（`/filter`）在通用数据层之外加了一层单据管控，规则集中在
`frontend/src/data/filter-rules.ts` 与 `frontend/src/api/filter-service.ts`：

- **扣单必填项**：滤料类型、反冲洗强度未填的单据整单扣住、不落库，弹窗逐项标出缺哪一项；
  运行水头损失允许后补，留空在列表与详情里显示「未填写」标记，和「取不到数」区分开。
- **历时区间**：反冲洗历时按 5~15 分钟（含边界）校验，区间外按非法值扣下。
- **编号唯一**：同一滤池编号重复登记直接驳回，重复提交只记一次；提交期间同步加锁防连点。
- **强度分档**：反冲洗强度按滤料类型对应档位校验（石英砂 12~15、无烟煤 10~12、
  陶粒 15~18、煤砂双层 13~16，单位 L/(s·m²)）；分档表存在页面下方可维护，
  持久化在 `waterworks-ops:filter-bands`，滤料更换、档位调整后保存即生效，
  新单据按新档位校验，并记录档位版本与更新时间。
- **整月提醒**：默认只看本月单据（按反冲洗时间归属月份），整月无单据时表格内提示
  「本月（YYYY-MM）暂无滤池反冲洗单据」。
- **取数失败与重试**：取数失败时列表清空并显示一次错误横幅 + 重试按钮；
  详情面板取同一次列表读取的数据源，重试成功后列表与详情数值对齐。
  页脚「取数异常演练」只置位一次失败，用于验证重试链路。
- **单据背面**：阀门顺序（停机先关进水阀再开排空阀；复役先关排空阀再开进水阀）
  印在打印单据背面，打印路由 `/filter/print/:id`，正面是单据、背面单独分页。
